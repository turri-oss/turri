# The conversion lost, changed and added nothing

The artifact holds a module as it was in the old ***plain syntax, word for word, the func-ids and scenario-ids the person confirmed, and the files the conversion wrote. Read each file it names from disk, and check every criterion. One violation fails the review; name it, with the functional spec or scenario and the words that differ.

1. **Every functional spec is there.** Each top-level `- ` bullet under `***functional specs***` of the module as it was is one `# <func-id>` heading in the module now, with the confirmed func-id, in the same order. No functional spec is missing, and none was added or split.
2. **Every body is its bullet, word for word.** Under each heading, the text is the bullet's text without its leading `- `, word for word, and its sub-bullets follow as `- ` bullets, word for word and in the same order. Nothing is reworded, shortened, merged, reordered or added - not a word, not a full stop.
3. **Every acceptance test is a scenario, word for word.** Each acceptance test nested under a bullet is a scenario under `***acceptance tests***` in that functional spec's test plain file: a `# <scenario-id>` heading with the confirmed scenario-id, then the acceptance test's text without its `- `, word for word, its sub-bullets as `- ` bullets.
4. **Nothing was added to the tests.** No scenario that was not an acceptance test: `***conformance tests***` is empty in every test plain file, and `***acceptance tests***` holds only the converted acceptance tests.
5. **Every functional spec has its test plain file.** Each is at `tests/<module>/<func-id>.plain`, with frontmatter `module:` set to the module's name and `func_id:` to its func-id, then `***conformance tests***`, then `***acceptance tests***`, each heading at the start of a line. A functional spec with no acceptance tests has the file with both sections empty.
6. **The rest of the module is untouched.** The frontmatter, `***definitions***`, `***implementation reqs***`, `***test reqs***`, comments and Liquid read exactly as they did, and no `***acceptance tests***` is left in the module.
7. **The ids are well formed.** Every func-id and scenario-id is lowercase letters, digits and hyphens only; func-ids are unique in the module, and scenario-ids unique within their functional spec.
