# Check the interface against the code

Below is a module's ***plain - each functional spec with its scenarios - and the interface the code of its features defines. From now on the ***plain is the source of truth and the code is regenerated from it: what it says of the interface must be what the original does, exactly. Check every interface fact it states against the code that decides it - each option's names, the value it takes, its choices and default; each command; each route's method, path, parameters, fields and status codes; each message, output format and exit code a user or a script sees; each environment variable. Read the definition and follow it: never take the ***plain's word, a name, a help text or a docstring when the code does otherwise. The agents that wrote it were offline and read in a hurry; expect mistakes.

When the part has an interface reference, its entries are listed: taken from the code, every literal checked against it. The ***plain must agree with it - an option, a choice, a default it gives otherwise is wrong, unless the code shows the reference is - and an option the ***plain names that the reference does not have is listed for you to settle against the code.

Correct what is wrong, and add what is missing of the interface it already describes: a choice left out, a default unsaid, an alias, a message's exact text, a field. A scenario that would fail against the original is corrected too. Call `submit_capture_corrections` once, with each correction: the functional spec's func-id - and the scenario's id when the correction is to the scenario - its whole new text, and why, citing the code. Change nothing else: a functional spec that holds keeps its words, behaviour that is not interface is not yours, and no fact is cut. None at all when everything holds.
